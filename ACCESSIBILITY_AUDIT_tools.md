# Deep Accessibility & Usability Audit — beast-cal.html, path.html, payment.html

Read all three files in full plus `ACCESSIBILITY_REPORT.md`. Computed real WCAG relative-luminance contrast ratios (Python, standard formula) for every color pair found in the CSS, and traced every interactive element's markup/JS to verify keyboard operability, labeling, and touch-target size. Grid cell sizes computed algebraically from the actual CSS box model at common viewport widths.

## tool/path.html

| # | Severity | Location | Problem | Fix |
|---|----------|----------|---------|-----|
|1| **Critical** | `path.html:236-292` | Grid cells are plain `<div>` elements (`document.createElement("div")`, line 236) with **no `tabindex`, no `role`, no keydown handler** — only `onclick`, `oncontextmenu`, and `touchstart/move/end`. The entire tool (setting start/end/obstacles/grades and reading results) is **100% unreachable and unoperable by keyboard** — a WCAG 2.1.1 (Level A) failure, not just a "small target" issue as the report framed it. | Make cells `<button type="button" tabindex="0">`, add `keydown` handling for arrow-key navigation + Enter/Space to trigger the same action as click, and a separate keyboard-accessible way to reach the long-press "cycle grade" action (e.g. a second key like Shift+Enter). |
|2| **High (size correction)** | `path.html:48,86-90` computed cell size | Report claimed "12-14px" cells; actual computed size (body padding 16px, `.grids-wrap` 2-col gap 12px, `.grid-card` padding 10px, `.grid` gap 2-3px, 5 columns) is **≈22px at 320px, ≈27.5px at 375px, ≈31px at 414px, ≈37px at 480px** viewport width — larger than reported, but still under the 40×40px recommended minimum at every common phone width, and two 5×5 grids are shown side-by-side which halves available width. | Report's fix direction (fewer columns or single-grid-at-a-time on mobile) is still correct; suggest stacking `.grids-wrap` to `grid-template-columns: 1fr` under 480px so each grid gets the full width (cells would then be ~60px+ at 375px). |
|3| **High** | `path.html:49-66` | Grade tiers (2-6, the actual point values 1/2/4/10/30) are conveyed **by color/border alone** inside the grid — no text, number, or icon on the cells themselves (only start `S` and end `E` get text). ## tool/payment.html

**What it does**: lets a player upload a Google Pay CSV export (from Google Takeout) and sums transactions where 설명(description) contains "벽돌주식회사" and 상태(status) is "완료", to reconcile in-app purchases.

| # | Severity | Location | Problem | Fix |
|---|----------|----------|---------|-----|
|1| **High (functional bug, not in report)** | `payment.html:161-176` vs `:70-73` | `downloadFiltered()` is fully implemented (builds a CSV blob of the matched rows and triggers a download) but **is never called from anywhere in the page** — grep confirms the only `onclick` handlers are `processCSV()` and `openLink()`. The `🌐` button (which *does* get enabled/disabled based on `filteredRows.length`, lines 152-154, clearly wired for a "download results" affordance) actually opens `https://takeout.google.com/settings/takeout` in a new tab instead. **The tool has no working way for a user to export the filtered CSV it computes**, despite the UI (button enable/disable state) implying that feature exists. | Either wire a genuine "결과 다운로드" button to `onclick="downloadFiltered()"`, or remove the dead function and clarify the 🌐 button's sole purpose (opening Takeout) in its label/instructions. |

## Corrections to ACCESSIBILITY_REPORT.md (verified wrong or already-non-issues)

1. **Dark-theme contrast claim is wrong for beast-cal.html specifically.** The report states `--text-dim: #7a7f99` gives 2.2:1 on the dark theme. **That CSS variable doesn't exist anywhere in beast-cal.html** (grep confirms 0 matches for `text-dim` or `7a7f99`) — beast-cal.html actually uses `--text-muted: #7b82a8`, which measures **5.03:1 on the page background** (passes AA) and only fails (3.98:1) in the narrower default-button-on-surface2 context (finding #2 above). The report appears to have generalized a forge.html-specific number to beast-cal.html without checking beast-cal's own palette; most of beast-cal's dark-theme text (body text 15.75:1, gold 11.88:1, success 10.83:1, danger 6.82:1, primary accent 6.30:1) **passes AA comfortably**.
2. **Report's path.html grid cell size ("12-14px") is inaccurate** — real computed size is ~22-31px across common phone widths (320-414px). Direction of the concern (too small for reliable touch) is still correct, just not the number.
3. **Report says beast-cal.html's checkbox/toggle has no explicit label** (folded into a general "폼 필드 레이블 부재" claim) — verified false: `#compareToggle` is correctly wrapped in a `<label>`, giving it a proper accessible name. Only the `<select id="effectFilter">` actually lacks one.
4. **payment.html was not assessed at all** in the original report (its scope statement says "계산기 5개, 도구 2개" but only path.html's grid was analyzed for tool/); the button-color failures, missing file-input label, and the dead `downloadFiltered()` function are new findings this pass surfaced.
5. Report's keyboard-navigation section flagged only `div.card` on `index.html`; it never caught that **path.html's entire interactive surface (the grid) is keyboard-inoperable**, which is a more severe (Critical, WCAG 2.1.1 Level A) gap than anything cited in the report for these three files.
